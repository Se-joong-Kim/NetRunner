# 고정 세트 450라운드 재측정 (2026-11-25)

GLM 응답 파싱과 재요청을 개선한 [PR #97](https://github.com/Se-joong-Kim/NetRunner/pull/97) 병합 후, 고정 세트 전체를 다시 측정했다. [PR #98의 재실행](benchmark-targeted-error-rerun-pr97-2026-11-25.md)은 이전에 실패한 51건을 대상으로 했다.

## 측정 조건

- 실행 커밋 `82c7955`. `fixtures/fixed_set`이 동결 커밋 `df932a3`의 세트와 같은 것을 확인했다.
- Windows Docker Desktop의 실험망에서 30개 시나리오를 방식별로 3회씩 실행했다. 방식당 90라운드, 총 450라운드다.
- GLM 네 방식에는 `opencode-go/glm-5.3-flash`를 사용했다. 방식 A는 규칙 기반이다.
- OpenCode의 기본 호출 제한은 300초다. 실제 호출에는 라운드의 남은 시간과 호출 제한 중 짧은 값이 적용된다.
- 실행 시간은 11월 25일 17:05~22:01 KST로 약 4시간 56분이었다.

## 결과

450건 중 449건을 채점했다. 장애 재현과 복구 확인은 각각 450/450 성공했다. 단계·원인 정확도는 기존 보고서와 같이 방식당 90건을 분모로 사용하고, 증상을 재현한 뒤 진단에 실패한 라운드는 오답으로 센다.

| 방식 | 채점 | 단계 정확도 | 원인 정확도 | 오탐 | 빈 진단 |
|---|---:|---:|---:|---:|---:|
| A | 90/90 | 89/90 (99%) | 86/90 (96%) | 0 | 1 |
| B | 90/90 | 48/90 (53%) | 45/90 (50%) | 18 | 24 |
| C | 90/90 | 67/90 (74%) | 66/90 (73%) | 11 | 13 |
| C-1 | 89/90 | 73/90 (81%) | 71/90 (79%) | 8 | 9 |
| C-2 | 90/90 | 70/90 (78%) | 67/90 (74%) | 12 | 11 |

빈 진단은 채점된 라운드에서 `findings`가 빈 목록인 경우다. 진단 실패 1건은 C-1의 `FS22-S2-NEWS`에서 발생한 JSON 객체 형식 오류였다. 해당 라운드의 장애 재현과 복구는 성공했다.

[11월 24일 보고서](benchmark-results-2026-11-24.md)와 비교하면 전체 진단 실패는 51건에서 1건으로 줄었다. 방식 B는 90건 모두 채점됐지만, 24건에서 원인을 제출하지 않았고 오탐도 18건 있었다. 방식 C-1은 이번에도 GLM 방식 중 원인 정확도가 가장 높았다.
