# 조합 장애 고정 세트 (composite_set)

장애 2~3개를 한 시나리오에 함께 심는 세트다(#107). `lab-check --dir fixtures/composite_set --repeat 3`으로 실험망에서 주입, 증상 확인, 복구를 확인한다. AI 진단과 채점은 하지 않는다.

## 구성

- 시나리오 13개(`cs01`–`cs14`에서 `cs13`을 뺀 것, `cs15`는 세트에 없음): 장애 2개짜리 10개, 장애 3개짜리 3개.
- 도메인: shop.lab 7개, news.lab 6개. https 시나리오는 2개다.
- 장애 종류: N1이 모든 시나리오에 들어가고, D4가 3개, D1과 D2와 T1이 각각 2개다. D3, T2, N3, S1, S2, H1, H2는 한 번씩 들어간다. B1·B2는 복수 장애 검사에서 거부되므로 넣지 않았다.
- 이 13개는 2026-11-27 `lab-check --repeat 3` 실행에서 세 번 모두 통과했다.

## 규칙

- 같은 묶음 장애는 한 시나리오에 하나만 넣는다(`validate` 규칙: D1·D2·D3·B2, T1/T2, S1/S2, H1/H2).
- N1+N2, D1~D3+D4, N3·N4와 비경로 장애의 조합은 `lab-check`에서 거부되므로 넣지 않았다.
- 손실(N2)은 넣지 않았다. 증상 확인이 DNS를 `dig +tries=1`로 한 번 질의하므로, 손실이 걸리면 질의 한 번이 5초 시간 초과로 실패해 같은 조합이 반복 측정에서 통과하지 못했다. 단일 장애 N2는 `fixtures/fixed_set`에 그대로 있다.
- 대역 제한(N4)은 넣지 않았다. N1 지연이 있으면 N4의 부하 지연 확인이 지터에 묻혀 같은 조합이 통과하지 못했다. 단일 장애 N4는 `fixtures/fixed_set`에 그대로 있다.
- 같은 DNS 확인 문제로 반복 측정에서 한 번 실패한 조합(`cs15`)은 뺐다. 확인 로직은 #111에서 다룬다.
- 모든 장애가 클라이언트에서 관측 가능해야 한다. 선행 장애에 가려지는 조합은 넣지 않았다. 가려진 장애를 채점에서 어떻게 셀지는 #106에서 정한 뒤 추가한다.

## 상태

- 실험망 확인(`lab-check --repeat 3`)을 13개 기준으로 통과했다. 이 확인은 실험망 쪽 판정이 흔들릴 수 있어서, 같은 세트의 다음 실행에서도 통과한다고 보장하지 않는다.
- 동결은 전원 동의 뒤에 한다(#107 후속 이슈).
